# lang-cards

Ihar's personal flashcard PWA (Vite + React + TS, FSRS via `ts-fsrs`). Hosted on Vercel; every push to `main` deploys.
Ihar talks in Russian. He learns Polish (B2, native Russian); other languages may be added later.

## The main job: turning material into cards

Ihar sends photos, screenshots, files or word lists. Turn them into cards, commit, push. No app code changes needed.

1. Read the material. Ask where to put it only if he didn't say and it isn't obvious; otherwise pick a group
   (lesson number, topic, grammar point) and say which.
2. Check for duplicates: search existing `public/decks/<lang>/**` for the same `front`. Skip or merge, never duplicate.
3. Write/extend the deck JSON (format below). Keep existing card `id`s unchanged — progress is keyed by id.
4. `npm run build` must pass (it validates decks: missing fields, duplicate ids, bad JSON).
5. Commit as the user (git author is already `Resip10 <resip810@gmail.com>`) and push to `main`.
6. Reply briefly: how many cards, which group.

## Layout

```
public/decks/<lang>/_meta.json         { "name": "Polski", "flag": "🇵🇱", "tts": "pl-PL", "chars": "ąćęłńóśźż", "order": 1 }
public/decks/<lang>/<group>/_meta.json { "name": "Лекции", "order": 1 }        (optional, any nesting depth)
public/decks/<lang>/<group>/<deck>.json
public/media/<lang>/...                images referenced by cards
public/decks/manifest.json             GENERATED by scripts/build-manifest.mjs — never edit by hand
```

A new language = new folder with `_meta.json` (`tts` is a BCP-47 code for speech, `chars` are the extra-letter
buttons shown in typing mode). The app shows a language switcher automatically.

Folder and file names: lowercase ASCII slugs (`lekcja-07.json`, `tematy/zdrowie/`). Display names go in `name`.

## Deck format

```json
{
  "name": "Лекция 7: здоровье",
  "order": 7,
  "cards": [
    {
      "id": "pl-l07-lekarz",
      "front": "lekarz",
      "back": "врач",
      "gender": "m",
      "hint": "lp. lekarza",
      "example": "Muszę iść do lekarza.",
      "exampleTr": "Мне нужно сходить к врачу.",
      "note": "Пояснение по-русски, если есть ловушка.",
      "tags": ["zdrowie"],
      "image": "pl/lekarz.jpg",
      "answers": ["lekarz"],
      "audio": "lekarz"
    }
  ]
}
```

Required: `id`, `front` (target language), `back` (Russian). Everything else optional.

- `id`: unique within the language, stable forever. Pattern `<lang>-<deck-short>-<ascii-slug>`.
- `gender`: `m` | `f` | `n` | `pl` for nouns.
- `hint`: short grammar tag shown on both sides: `ndk / dk` for aspect pairs, case after a verb, plural, etc.
- Aspect pairs: `"front": "robić / zrobić"` — typing mode then expects both forms separated by `/`.
- Verb government: `"front": "czekać na + B."` with `"answers": ["czekać na"]` and `"audio": "czekać na"`
  (grammar notation like `+ B.` is stripped from speech and typed answers anyway, but be explicit).
- `example` + `exampleTr`: one natural sentence, preferably from the source material.
- Useful for a Russian speaker: flag false friends and case differences from Russian in `note`.
- Fix obvious OCR errors and diacritics; don't invent content the source doesn't support unless asked.

## App notes

- Two FSRS tracks per card: `recognize` (PL→RU, audio) and `recall` (RU→PL, typing). Progress lives in the
  browser's IndexedDB only; Settings has backup export/import.
- Decks are fetched network-first by the service worker, so new cards appear on next app open without updating the app.
- Speech: browser `speechSynthesis`, no external service.
